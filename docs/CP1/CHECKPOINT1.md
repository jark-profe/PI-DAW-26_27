# 📌 Checkpoint 1: Definición Inicial del Proyecto

¡Bienvenidos al primer hito de vuestro Proyecto Intermodular! El objetivo de esta fase es **definir la idea general de vuestra aplicación web y acotar su alcance** para asegurar que sea un desarrollo viable durante el curso.

Un error muy común al inicio es intentar abarcar demasiado o perderse en decisiones tecnológicas antes de tener claro *qué* problema resuelve la aplicación. En este hito nos centraremos exclusivamente en el concepto y el valor del proyecto.

---

## 📋 ¿Qué debes entregar en este Checkpoint?

Deberás completar la sección del Checkpoint 1 en tu repositorio de GitHub incluyendo los siguientes 4 puntos:

1. **Título del Proyecto:** Nombre público de tu aplicación web.
2. **Tipo de Aplicación:** Categoría o tipología del proyecto (ej. *Plataforma de gestión, E-commerce, Red social temática, Plataforma de reservas, Gestor de eventos, etc.*).
3. **Temática:** Sector o ámbito específico en el que se enfoca (ej. *Educación, Salud y Deporte, Hostelería, Logística, Entretenimiento, etc.*).
4. **Descripción del Proyecto:** Un resumen explícito de **entre 50 y 100 palabras** explicando en qué consiste la aplicación, a quién va dirigida y qué necesidades resuelve.
   * ⚠️ **REGLA OBLIGATORIA:** En la descripción **NO se deben mencionar tecnologías concretas** (está prohibido escribir cosas como *"desarrollada con React y Laravel"* o *"con base de datos MySQL"*).

---

## ⛔ Errores frecuentes que causan un "NO APTO"

Para obtener el **APTO** en Moodle/GitHub en este hito, asegúrate de no cometer los siguientes errores habituales:

* **Sobredimensionar el alcance (Efecto IA):** Si le pides a una IA que redacte tu idea, suele incluir pasarelas de pago complejas, chatbots avanzados, motores de recomendación o analítica masiva. Recuerda que eres **un solo programador/a**. Limítate al núcleo básico (MVP).
* **Mencionar tecnologías en la descripción:** La descripción en esta fase debe ser estrictamente funcional (qué hace la app, no cómo está programada). Las tecnologías se seleccionarán y justificarán en el Checkpoint 3.
* **Proponer una página web estática:** Si tu idea no requiere base de datos, autenticación de usuarios ni gestión de permisos (CRUD), no es válida para un perfil DAW.
* **Extensión incorrecta:** Presentar descripciones de menos de 50 palabras (vagas) o de más de 100 palabras.
