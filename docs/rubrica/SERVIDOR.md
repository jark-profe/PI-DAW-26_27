### ⚙️ Rúbrica: Funcionalidad Backend y Seguridad - Servidor (20%)

| Criterio | Excelente (100% - 90%) | Notable / Aceptable (89% - 60%) | Suficiente (59% - 50%) | Insuficiente (< 50%) |
| :--- | :--- | :--- | :--- | :--- |
| **Capa de Datos y Operaciones CRUD (6%)** | Operaciones CRUD completas y optimizadas sobre la base de datos. Gestión impecable de relaciones entre entidades, integridad referencial y validación estricta del formato de los datos de entrada. | Operaciones CRUD funcionales para las entidades principales del sistema, aunque con pequeñas omisiones en validaciones de entrada o consultas secundarias no del todo optimizadas. | Las operaciones CRUD básicas funcionan, pero existen fallos puntuales en la actualización/borrado o la base de datos permite guardar datos inconsistentes por falta de validación. | Las operaciones CRUD están incompletas o fallan frecuentemente. No existe una correcta integración con la base de datos o se producen errores no controlados en el servidor. |
| **Autenticación y Gestión de Sesiones (7%)** | Flujo completo de Login y Logout con persistencia de sesión segura (Cookies `HttpOnly`, tokens JWT bien configurados o equivalente). Hash seguro de contraseñas y expiración/renovación correcta de sesiones. | Login y Logout funcionales con persistencia de sesión correcta, aunque la configuración del token/cookie presenta leves desajustes de seguridad (ej. expiración excesivamente larga o falta de algún flag de seguridad). | Autenticación básica funcional, pero el mecanismo de sesión es inseguro (ej. tokens almacenados en `localStorage` inseguro o contraseñas almacenadas en texto plano/hash débil). | El proceso de autenticación falla, la sesión no se persiste de forma correcta o el Logout no destruye el acceso del usuario, permitiendo accesos ilegítimos. |
| **Autorización RBAC y Protección en Servidor (7%)** | Control de acceso por roles (Admin, Usuario, Anónimo) verificado estrictamente en el Backend mediante middleware/interceptores. Cada endpoint valida identidad y permisos devolviendo códigos HTTP adecuados (`401`, `403`). | Sistema RBAC funcional en la mayoría de endpoints clave, pero con alguna ruta secundaria donde la verificación de permisos en el servidor es laxa o devuelve códigos de error inadecuados. | El sistema distingue roles pero la protección depende en exceso del cliente; existen endpoints en el backend que no verifican correctamente la identidad o el rol antes de operar en la BBDD. | Falta de protección en el servidor. Cualquier usuario autenticado (o anónimo) puede consumir endpoints restringidos o modificar datos de otros usuarios manipulando las peticiones directamente. |
