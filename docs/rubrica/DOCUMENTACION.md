### 📂 Rúbrica: Documentación en GitHub (5%)

| Criterio | Excelente (100% - 90%) | Notable / Aceptable (89% - 60%) | Suficiente (59% - 50%) | Insuficiente (< 50%) |
| :--- | :--- | :--- | :--- | :--- |
| **Cumplimiento y Calidad de Apartados (3%)** | Todos los apartados solicitados  están presentes, completos y rellenados correctamente con la información real del proyecto. | Se incluyen todos los ficheros y apartados solicitados, aunque alguna sección secundaria contiene explicaciones demasiado breves o poco desarrolladas. | Faltan algunos apartados secundarios o la información de los ficheros está incompleta, con texto de plantilla sin modificar o explicaciones muy superficiales. | Faltan apartados clave. La documentación en GitHub es inexistente, está desactualizada o no refleja el proyecto real. |
| **Formato Visual y Maquetación Markdown (2%)** | Maquetación impecable en GitHub: uso excelente de encabezados, listas, tablas, enlaces relativos entre ficheros, bloques de código sintácticamente coloreados y elementos visuales (diagramas/capturas). | Formato visual limpio y bien estructurado. Uso correcto de Markdown y enlaces entre documentos, aunque con pequeñas imperfecciones de maquetación o pocos apoyos visuales. | Formato básico o poco cuidado. Dificultad para navegar entre ficheros, mal uso de los niveles de encabezado o tablas desalineadas que dificultan la lectura. | Maquetación descuidada o rota al renderizarse en GitHub. Texto plano sin estructurar, enlaces rotos entre ficheros `.md` o ausencia total de formato técnico. |
