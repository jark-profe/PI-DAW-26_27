### 💻 Rúbrica: Funcionalidad Frontend - Cliente (20%)

| Criterio | Excelente (100% - 90%) | Notable / Aceptable (89% - 60%) | Suficiente (59% - 50%) | Insuficiente (< 50%) |
| :--- | :--- | :--- | :--- | :--- |
| **Vistas del Sistema y Control de Acceso (7%)** | Implementación completa de vistas públicas, privadas protegidas estrictamente por rol y perfil de usuario (consulta/edición). La navegación bloquea accesos no autorizados sin fallos. | Vistas públicas, privadas y de perfil implementadas, aunque con pequeños fallos de renderizado o redirecciones no del todo fluidas al cambiar de rol. | Las vistas principales existen y funcionan, pero el control de acceso por roles es frágil o la vista de perfil tiene funcionalidades incompletas (ej. no permite editar). | Faltan vistas esenciales del sistema o no existe protección de rutas privadas, permitiendo el acceso a secciones restringidas sin autenticación. |
| **Gestión de Formularios y Validación (7%)** | Formularios de Registro, Login, Perfil y operaciones CRUD completamente funcionales. Validación de datos en tiempo real con mensajes de error o éxito claros para el usuario. | Formularios funcionales para los flujos principales, con validaciones correctas pero con feedback visual mejorable o mensajes de error poco descriptivos. | Los formularios permiten enviar datos, pero carecen de validación adecuada en cliente o muestran errores genéricos/crudos cuando el envío falla. | Formularios rotos, incompletos o que no realizan el envío de datos correctamente. Carece por completo de validación e información al usuario. |
| **Estado, Componentes y Navegación (6%)** | Excelente gestión del estado global/local, código modular con componentes reusables, paginación fluida y control visible de errores de red (loaders, estados vacíos, modales). | Buena estructuración en componentes reusables y gestión del estado correcta, aunque la paginación o el manejo de estados de carga/error presenta pequeños descuidos. | La aplicación funciona, pero hay duplicación excesiva de código en componentes, la gestión del estado es caótica o no hay avisos visibles cuando falla la conexión. | Código monolithic sin componentes reusables, el estado del cliente se pierde constantemente al navegar o los fallos de red congelan la interfaz sin aviso. |
