### 🚀 Rúbrica: Despliegue y Entorno (10%)

| Criterio | Excelente (100% - 90%) | Notable / Aceptable (89% - 60%) | Suficiente (59% - 50%) | Insuficiente (< 50%) |
| :--- | :--- | :--- | :--- | :--- |
| **Entorno Real y Disponibilidad (3%)** | La aplicación está desplegada en un servidor o plataforma cloud accesible públicamente vía URL única. Todos los servicios están en producción, sin caídas ni errores de carga durante la evaluación. | Despliegue funcional en producción mediante URL pública, con fallos de disponibilidad muy puntuales o lentitud en el arranque inicial de los servicios cloud. | La aplicación es accesible públicamente, pero presenta inestabilidad evidente (caídas frecuentes, servicios que se desconectan o tiempos de respuesta excesivos). | No se realiza el despliegue en un entorno público real o se pretende evaluar sobre `localhost`. La aplicación no es accesible vía URL pública. |
| **Seguridad HTTPS / SSL (3%)** | La aplicación utiliza un certificado SSL/TLS válido (HTTPS) en todo el dominio. La navegación, llamadas a la API y conexiones a BBDD están completamente cifradas sin advertencias de seguridad. | Certificado SSL/TLS válido instalado y funcional, aunque con advertencias menores no bloqueantes en el navegador (ej. peticiones mixtas a recursos HTTP secundarios). | Certificado SSL presente pero mal configurado o caducado, provocando avisos de seguridad que requieren confirmación explícita del usuario para acceder. | Ausencia de cifrado SSL/TLS. La aplicación opera exclusivamente sobre HTTP inseguro o con certificados autofirmados inválidos que impiden el acceso. |
| **Containerización con Docker (4%)** | Todos los servicios (Frontend, Backend y BBDD) están correctamente containerizados. El repositorio incluye un `Dockerfile` optimizado y/o `docker-compose.yml` que levanta la pila completa sin errores. | Servicios containerizados y funcionales mediante Docker, pero el archivo `docker-compose.yml` o `Dockerfile` presenta fallos menores de optimización (ej. tamaño excesivo de imagen o rutas fijas). | Se utilizan contenedores para parte del sistema (ej. solo BBDD o solo Backend) o los archivos de configuración en el repositorio requieren ajustes manuales para poder ejecutarse. | Ausencia de containerización. No se incluye `Dockerfile` ni `docker-compose.yml` en el repositorio, o los archivos proporcionados están rotos y no compilan. |
